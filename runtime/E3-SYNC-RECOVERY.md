# Sync publication recovery

This isolated packet fixes two reproduced failures: a foreground native Refresh advances the app-owned provider checkpoint before observation starts, and a lost/revoked publication leaves the host scan checkpoint behind an already committed native page. The host cursor is now a publication cursor; it never feeds the provider engine's private continuation.

Each state-changing native mailbox commit captures a checksummed page in an app-owned encrypted handoff ring (at most128 pages, each at most900KiB). The mailbox index records the commit sequence. A restart reconciles a prepared handoff against that durable index witness: a pre-index interruption is aborted; a post-index interruption is committed. Query-only cache writes allocate no handoff and do not claim native completion. Missing/evicted handoffs fail with EMAIL_SYNC_PUBLICATION_REBASELINE_REQUIRED, never a checkpoint reset or silent skipped page.

The observation consumer is pinned to its full current consent/scope, immutable connection/account, client fingerprint, actual custody generation, descriptor and released item budget. One exact pending page is durable before disclosure. A newly released and freshly authorized read Run can publish that same immutable page without another provider read. It never replays or edits the prior unknown Run. Only the next released input cursor acknowledging the previous page advances that consumer. The host advances its own checkpoint only after its existing public result transaction accepts the page.

Legacy native state without a retained handoff uses bounded cache bootstrap. It scans at most25 cached rows per page, including deleted rows in the scan budget. Bootstrap never emits inferred tombstones, never claims complete coverage, and never changes native provider state. Subsequent native work starts from the retained current provider cursor. A reviewed new custody/scope bootstraps retained app-owned metadata rather than accepting an old producer's authority.

Stable native logical resource IDs and the existing foreground UUID mapping are preserved. Explicit committed provider tombstones retain those IDs. Tombstone revisions now bind the immutable publication cursor and stable account/logical identity, so later native pages do not reuse a custody-generation-only deletion revision. MIME/file catalogs, drafts and Send history are untouched.

Online authority remains fresh at Run entry, every actual provider/refresh network request, checkpoint commit, publication persistence and final disclosure. Pure row/handoff integrity checks run under the existing held session/index locks and local cancellation/deadline/custody fences. There is no cross-request authority cache, new permission, provider effect, deadline extension or scheduler. All51 frozen vendor files remain byte-exact.

Validation covers both original red reproductions, reboot/lost publication, ordered foreground handoffs, explicit overflow/interrupted eviction, foreign account/principal/client/generation denial, late revocation, pre/post-index crash, bounded deletion scan, and actual frozen Gmail history expiration followed by current global404 deletion. Large inventory/Graph delta/IMAP UIDVALIDITY fault matrices and timers/effect jobs remain separate parity work. This packet is local test evidence; it does not claim live background recovery before deployment acceptance.
