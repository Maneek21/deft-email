The `0.3.1-e3.1` candidate preserves the frozen query compiler's unsupported result. `resource_list` returns bounded public `search` diagnostics, no items or cursor, and no freshness field. It performs no provider I/O and commits no cache or checkpoint for an unsupported query. Clients must retain their previous view rather than display an authoritative empty mailbox.

Only the exact canonical selector `in:archive` uses the app-owned Gmail Archive adapter. It requests messages outside Inbox, Sent, Drafts, Trash and Spam, then verifies those exclusions against each hydrated message's current labels. Messages that changed labels during listing are omitted and make `query_complete` false. Pagination binds the selected account, current custody generation and complete scope, fixed selector, and exact page size. Frozen OAuth, Gmail metadata, logical/conversation identity, source nomination and cursor primitives remain unchanged. Mixed Archive expressions and negated `in:` expressions remain explicitly unsupported; this is not a general compiler extension.

Current host authority and captured custody identity guard provider fetches and final disclosure. A mid-hydration denial returns no rows and creates no cache checkpoint. The focused tests use synthetic provider responses, including all five excluded roles, cursor crossing and revocation. They do not claim live Gmail Archive acceptance.
