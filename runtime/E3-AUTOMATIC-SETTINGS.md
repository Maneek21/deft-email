# E3 preferences and initial default signatures

This isolated packet adds account-owned `preferences` with exactly `external_images: ask|always`, one active row, 8192-byte limit and no files. Create is Ask-only. Save is CAS-protected under the account/store collection lock; archive, receipts and original-request status retain the existing settings behavior. Missing preferences mean Ask at the trusted client. A preferences read returns only the explicit app-owned policy nomination alongside the validated record. The runtime never fabricates `human_save`: the host independently derives it from an exact completed current-owner Save journal before automatic image loading.

Signatures accept the optional strict `automatic: {schema_version: deft.signature_automatic.v1, enabled: boolean}`. Missing/false remains manual; Create cannot enable it. Existing human Save is the current-write channel for activation. The native 32 unique verified identities and 64KiB account aggregate remain atomic, including marker bytes.

`signature_default` is admitted only with `invocation_mode: initial` on Prepare, immutable prepared snapshot, and Apply. Absent mode preserves existing manual operations; a manual operation cannot use initial mode. Source activation, placement, exact current verified From or explicit native primary identity, draft status and revision/content_revision 1 are checked while holding sorted source/destination collection locks. Apply rechecks the source and destination CAS, current custody/generation/identity/primary, both permissions and immutable expiry before commit. No first-alias fallback or automatic replay. Existing draft text, recipients, files, origin and reply context are preserved; the native terminal marker uses the source entry revision. Existing edited terminal regions and noninitial drafts are denied for automatic application.

The current native primary address is intersected with verified sender identities and returned as `primary_identity` (or null) on metadata and full record read. An awaited authority check changing the primary with an unchanged alias set denies Apply. Metadata does not authorize a subsequent operation.

Every operation retains current host checks and exact app-owned custody/account scope. Existing paired consent proofs, 5-minute immutable preparation ceiling, 30-second invocation deadline, original UUID lost-ack status recovery and no provider effect behavior are unchanged. Graph-selected factories are preserved. All 51 vendor files remain byte-exact. This packet does not implement preferences for provider mirrors, outbox/Knowledge toggles, automatic Send, template parameters or mailto intake.

The additive metadata is validated by explicit closed runtime checks, then the existing result shape is checked against the currently installed public Kit17 schema. This supports the existing packed consumer while root prepares the additive Kit release; no private host import or mutable workspace dependency is introduced.
