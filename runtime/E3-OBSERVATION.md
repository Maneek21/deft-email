The `0.3.1-e3.2` candidate adds an explicit opt-in observation consumer using the existing public resource-sync v3 channel. It does not grant background access. The host must separately admit current human consent, a current connected account and a reviewed metadata descriptor before creating each Run.

Optional operator configuration `resource_sync_channel_files` is an array of1–32 distinct absolute private file paths. Each file is exactly `{channel_url,observation_authority_url,credential,registration}`. The credential is exactly `{session_id,session_token}` from the reviewed v3 channel; registration contains the same seven connection pins used by the runtime. URLs share one HTTPS origin, with exact paths `/api/app-resource-sync-channel/v3` and `/api/app-resource-observations/runtime`. Credentials are not refreshed or inferred from the connection, browser, data or Send credentials. Existing configurations without this field retain their behavior.

`createResourceObservationRunner` exposes `runOnce(signal)` and `executeClaim(claim,started,signal,emit?)`. It validates the exact public claim/Start and frozen `EMAIL_METADATA_DESCRIPTOR` (key inbox or mail_index). A durable app-owned encrypted Run journal seals the exact released identity/input, current consent snapshot and actual custody generation before the first provider request. A reviewed reattachment additionally requires the current lineage receipt and exact generation. Current online authority guards every provider fetch, checkpoint and disclosure; frozen native custody inspections also enforce generation. Session serialization, provider token locks and app-owned cache checkpoint ordering are retained.

The output is the frozen bounded scalar metadata projection with account-scoped logical IDs and original data revisions. `body_status:lazy`, `files_status:lazy|unknown|none` and empty attachment links are intentional metadata-only observations. Full original/source/CID/files remain lazily available through app-data. This runner does not stage attachment bytes or replace the native source/file cache. Host admission must reject an incompatible pre-existing attachment catalog for this metadata-only descriptor.

Completed journal recovery may disclose the exact saved page under fresh current authority and unchanged custody. A started or indeterminate journal never repeats provider I/O. Revoked/expired authority publishes no page. A failed read is not permission to replay its Run: a future observation requires a separately admitted current Run under the host's existing lease/checkpoint/recovery rules. The runner creates no second scheduler and issues no Send, mutation or channel renewal.

The optional process worker polls the public channel at most once every five seconds after an attempt; the host remains the only scheduler. `start_observation_workers:false` disables it for controlled fixtures. Test-only awaited phase hooks are `before_provider`, `before_checkpoint` and `before_disclosure`, carrying only the Run UUID. No content, token, MIME or provider URL is logged.
