# Review and candidate packaging

The current endpoint is human review in [Email PR 1](https://github.com/Maneek21/deft-email/pull/1), with compatible Host and Author Kit changes reviewed separately in [Deft](https://github.com/Maneek21/Deft). Do not merge, enable auto-merge, create release tags or publish releases as part of this preview review. Public candidate downloads are immutable evidence of their exact historical source; they are not accepted releases.

Integrate reviewed changes on a branch descended from the current PR head, preserving the previous source history. Push only a verified fast-forward to the existing PR branch. Keep generated build outputs, private configuration, tokens, custody, mailbox data and operational evidence out of Git.

Set the root and App package version together and update the matching App lockfile version entries. `app/build.mjs` reads `app/package.json`. Runtime version metadata must describe its actual source delta; the current App `1.9.0-preview.6` and Runtime `0.4.0-preview.6` both pin sealed Kit34, SHA256 `d5b0c498025684e4eae9fafe950846794b39874fac1f3277914e7e3c61bd93ef`. Generic Host schema120 is required for App6's signed `allow_until_revoked` policies and optional private draft-note form; exact-message Send review is unchanged. Older Kit30/32/33 remain historical artifacts; never overwrite a sealed package to update prose or align version numbers. Preserve all prior archives and build receipts.

Run locked dependency installation, Kit pin verification, Runtime vendor provenance, App build/package/UI checks and the focused Runtime checks in [CI](../.github/workflows/ci.yml). Build off the demo server. A clean build proves packaging; it does not prove public installation or provider delivery. Require the exact integrated Host's protected Type Check, Test API, Build, Production Image + Browser Smoke, Versioned Upgrade, CodeQL and Dependency Review checks. A custom closure or an older passing head does not substitute for those checks.

For a frozen candidate, build the App twice and verify identical package bytes. Record its package SHA256, canonical manifest digest, Experience artifact digest and worker hash. Run `npm run package:source` and retain `dist/source-manifest.json`; it records per-file hashes and the complete Email and Runtime archive identities. Provide corresponding source and license notices with any publicly served candidate executable. Keep previous candidate asset manifests immutable; write a new manifest for changed artifacts.

The Host's schema release value, image version, portable image configuration and Docker manifest/index identity are distinct pins. Use the compatible source/image recorded in [compatibility](compatibility.md), preserve actual schema authority, and never infer compatibility from a preview version label alone.

An App package update changes authority-bound digests even when only Worker presentation changes. Follow [setup](setup.md) and the supported protocol7 upgrade review: drain original work, require zero blockers, activate the exact reviewed package, obtain current admission/resource/action registrations and reattach the retained accounts through public v2 review/activation. The upgrade does not silently carry forward authority. Preserve records and original terminal/unknown Run journals; never replay them as an acceptance test.

Root owns capacity, the sole Runtime writer, deployment backup/recovery, public sideload and human authority review. Required gates remain the isolated empty-database bootstrap, fresh public upload/stage/review/activate and the ordinary Email smoke journey with independent recipient verification. Re-fetch the exact reviewed source and public dependency assets into a new directory and verify advertised checksums and commands before describing a clean installation as reproducible. Any executable change after freeze requires new build pins and the affected acceptance checks.
