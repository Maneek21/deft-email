# Preview limitations and release gates

Required preview acceptance: two-account isolation, explicit foreground Refresh, text/HTML/images, file access, save/reopen draft, recipient controls, attachments, ordinary reviewed Send with independent receipt/byte verification, reply modes, search/read/unread/archive, Task with full native details and Email source backlink, automatic Knowledge capture with source return, explicit Until revoked opt-in/revocation with finite technical renewal, and controlled restart. Measure cold Inbox, source return and image completion on the final combined stack; fixture timings are not live latency evidence.

Deferred: automatic recovery of unknown provider outcomes, automatic Knowledge policy provisioning and notifications, broad history migration, optional delegated tools/Calendar/Contacts, provider parity, production-scale certification and full mobile design. Retain existing encrypted records, original recovery receipts and unknown send journals. Removing an optional entry point never authorizes deleting its records or replaying its effects.

Manual Refresh fetches through the foreground path. Disabling background consumption does not make a blocked publication checkpoint complete. Use supported Host lifecycle controls to defer automatic observation; do not reset its cursor to manufacture a pass. The setup guide documents a new foreground-only Runtime configuration, not an instruction to overwrite an existing operator configuration.

The Runtime production CLI requires a POSIX local persistent filesystem and one service UID/writer. Windows is for build and permitted synthetic fixtures. No NFS/SMB/shared writer deployment is supported. Keys and durable encrypted state must be preserved across restarts and compatible upgrades. An uncertain Send is inspected through its original result; it is never retried automatically.

Clean build proves packaging. Local fixtures prove their specific contracts. Only ordinary UI actions on a compatible installation plus independent recipient verification prove the live smoke journey. The final release report must include actual timings, authority windows, accepted digests, fresh sideload rehearsal and current screenshots. A timestamped screenshot sequence may be rendered as a walkthrough video, with original screenshots retained and the sequence identified as such; it is not a continuous recording. Missing required evidence remains an unverified gate.

The preceding Host `25492e34` / schema 118 and App preview.3 passed real Compose, incomplete-draft save/reopen, PDF persistence through Runtime restart, one reviewed Send with independently matched recipient MIME/PDF bytes, and HTML/image acceptance. Its Task publication ended unknown with no accepted checkpoint and was not replayed. These are exact historical results, not acceptance of App `1.9.0-preview.7` / Runtime `0.4.0-preview.10` with Kit35.

The current App12/Runtime14 candidate uses Kit38 for the App and unchanged Kit35 for Runtime. It requires generic Host schema120 and current governed-document menu and target-aware resource-refresh integration. Top-menu Task/Knowledge nomination, separate subject/recipient metadata, account-specific automatic image defaults, displayed-account Refresh, technical-renewal recovery and guarded source reuse are implemented; installed acceptance of these exact artifacts remains pending. A saved ask preference and explicit Host image policy still take precedence. Optional private notes, reviewed Until revoked permission and exact-message Send review remain. Earlier provider delivery, restart, Task and source-navigation receipts retain their exact historical scope; one successful Send does not close the full acceptance matrix.

Require current Host and Email security/dependency checks, preserved finding dispositions, the protected branch's required checks and exact merged-tree review. Historical findings and audits describe their original commits only; neither an earlier clear audit nor an earlier HIGH advisory establishes the current head's status. A failed optional audit must remain visible, and a clean source check does not establish installed acceptance.

Disable/revoke are separate from uninstall. A successful retention-aware uninstall is not available through the current Host path; do not describe uninstall as working. Preserve unknown journals and retained account data.

An older demo reached 32 registrations, 30 action channels and approximately 16.1 KiB of its 16 KiB Runtime configuration budget. These are preview operational ceilings, not a reason to delete historical authority references or raise limits. Operator capacity and current authority must be reviewed before another upgrade. Until revoked is available only where the signed policy opts in and a current review accepts that mode; initial enrollment and all reviews, requests and Runtime leases remain finite. An expired technical lease is not revived. A backup checksum is not a restore rehearsal.
