# Preview limitations and release gates

Required preview acceptance: two-account isolation, explicit foreground Refresh, text/HTML/images, file access, save/reopen draft, recipient controls, attachments, ordinary reviewed Send with independent receipt/byte verification, reply modes, search/read/unread/archive, Task with Email source backlink, finite-authority renewal and controlled restart.

Deferred: automatic observation recovery, Knowledge/notifications, new background renewal architecture, broad history migration, optional delegated tools/Calendar/Contacts, provider parity, production-scale certification and full mobile design. Retain existing encrypted records, original recovery receipts and unknown send journals. Removing an optional entry point never authorizes deleting its records or replaying its effects.

Manual Refresh fetches through the foreground path. Disabling background consumption does not make a blocked publication checkpoint complete. Use supported Host lifecycle controls to defer automatic observation; do not reset its cursor to manufacture a pass. The setup guide documents a new foreground-only Runtime configuration, not an instruction to overwrite an existing operator configuration.

The Runtime production CLI requires a POSIX local persistent filesystem and one service UID/writer. Windows is for build and permitted synthetic fixtures. No NFS/SMB/shared writer deployment is supported. Keys and durable encrypted state must be preserved across restarts and compatible upgrades. An uncertain Send is inspected through its original result; it is never retried automatically.

Clean build proves packaging. Local fixtures prove their specific contracts. Only ordinary UI actions on a compatible installation plus independent recipient verification prove the live smoke journey. The final release report must include actual timings, authority windows, accepted digests, fresh sideload rehearsal and current screenshots. A timestamped screenshot sequence may be rendered as a walkthrough video, with original screenshots retained and the sequence identified as such; it is not a continuous recording. Missing required evidence remains an unverified gate.
